# 交付范围与验收

**核心要求：不交付半成品。** 每个对用户或管理员可见的模块，上线时必须是完整可用的：所有子功能、权限差异、状态与错误反馈齐备。做不完的功能不上线，而不是上线一半。

## 范围原则

| 原则 | 含义 |
|---|---|
| 以模块为交付单位 | 一个模块要么整体交付，要么整体不出现；不出现“按钮在但点不了”“页面空壳” |
| 成对功能同批交付 | 例如邀请树（查看）与剪枝（处置）、红包发行与领取、商店购买与卡券中心兑换 |
| 未完成即隐藏 | 暂不交付的模块通过功能开关与菜单权限整体隐藏，直接访问返回 404 |
| 前后端同批 | 前端模块依赖的后端接口必须是已实现状态；仍为 planned 的接口不允许前端先行上线 |
| 首期包含 Mini App | 桌面端与 Mini App 同一批次验收 |

## 首期范围

| 区域 | 模块 |
|---|---|
| 个人区 | P1 认证与初始化 · P2 首页 · P3 我的媒体 · P4 线路 · P5 积分与红包 · P6 我的商店与卡券中心 · P7 心愿中心 · P8 发现 · P9 个人资料 |
| 管理区 | A1 用户管理与邀请树（含剪枝） · A2 商店、红包与积分运营 · A3 媒体服务器与账号 · A4 推流节点与线路 · A5 心愿管理、通知与计划任务 |

| 移动端 | Mini App |

范围外：订阅、工作流、日历、整理、站点管理（已移除）。

## 模块验收清单（每个模块都必须满足）

1. **功能齐全**：模块页列出的每个子功能都可用，展示与交互符合描述。
2. **权限正确**：user（normal / vip / whitelist）、admin、super_admin 各自看到与能做的内容符合[角色矩阵](/roles-permissions)；越权访问返回 403，且后端同样拒绝。
3. **状态完整**：加载、空、错误、仅查看、锁定、功能关闭、离线都有对应呈现（[通用状态](/states-errors)）。
4. **账号门控正确**：被管理员禁用的用户被全站阻断；媒体账号到期或停用只限制 Emby 相关功能，续期可用。
5. **并发与幂等**：版本冲突返回 409 并有提示；兑换、签到、领取红包重复提交不产生重复结果。
6. **审计**：所有写操作类管理动作可在审计日志中检索（积分调整必须记录）。
7. **多语言**：简体中文与 English 文案齐全。
8. **移动端可用**：窄屏下无横向溢出，菜单可操作。

## 端到端验收场景

| # | 场景 | 通过标准 |
|---|---|---|
| 1 | 空库首启 → 初始化 → 登录 → 可播放 | 无需管理员额外干预，全链路完成 |
| 2 | 邀请码注册 → 签到 → 兑换注册码 → 开通账号 | 积分账本一致，余额不为负 |
| 3 | 账号到期 → 仍可登录 → 兑换续期码续期 | Emby 恢复可用，期间 EMS 功能不受影响 |
| 4 | 心愿：购买点数 → 电影/单集/多集/整季报价与提交 → 管理员处理 → 待处理过期退款 | 价格和余额来自后端;提交事务内复算覆盖与扣费;过期退款至多一次 |
| 5 | 管理员发红包 → 用户领取；打开“用户发红包”开关后用户可发 | 开关即时影响用户端按钮 |
| 6 | 管理员积分调整 | 显示剩余额度，超额被阻止，审计可查 |
| 7 | 剪枝 → 查看树 → 回滚 | 管理员与超管豁免；会话失效；回滚恢复 |
| 8 | 新建节点与线路 → 用户可见 / 锁定 | 单线路无选择器，会员线路对 normal 用户锁定 |
| 9 | 不同角色登录对比菜单 | 与[交互演示](/roles-permissions#交互演示-不同身份看到的菜单)一致 |
| 10 | Mini App：绑定 → 签到 → 商店 → 求片 | 与桌面端数据一致 |
