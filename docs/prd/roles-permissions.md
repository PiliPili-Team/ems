# 角色、层级与权限

## 两个独立维度

| 维度 | 取值 | 作用 |
|---|---|---|
| **角色 Role** | `user` · `admin` · `super_admin` | 决定能否进入管理区与超管专区 |
| **层级 Tier** | `normal` · `vip` · `whitelist` | 决定会员权益：可见线路、可用功能；whitelist 优先于 vip |

两者互不隐含：管理员也有自己的层级，但管理能力只由角色与权限点决定，不由层级决定。

## 可见 ≠ 可编辑

同一个页面，不同角色可能“看得到但改不了”。前端统一用四种呈现表达：

| 状态 | 菜单 | 页面内 | 直接访问 URL |
|---|---|---|---|
| **可操作** | 正常显示 | 全部控件可用 | 正常 |
| **仅查看** | 正常显示 | 写操作控件隐藏；页头显示“仅查看”标签 | 正常 |
| **锁定** | 显示，附锁图标 | 内容模糊或只读，并给出升级入口（如跳转商店） | 显示锁定说明 |
| **不可见** | 不显示 | — | 跳转 403 页 |

另有两种“功能不可用”：

- **功能开关关闭**（如积分功能关闭）：菜单隐藏，直接访问进入 404。
- **媒体账号不可用**：页面保持可访问，仅 Emby 相关按钮置灰并说明原因（见下）。

## 管理员默认只读,写权限逐项授予

超级管理员默认拥有全部读写。**管理员默认只持有读权限**:能进入所有管理页、查看数据,但没有任何写操作;每一项写权限由超管在“超管专区 → 管理员管理”里按项授予,授予与收回立即生效。

| 域 | 管理员默认(读) | 可授予的写权限 |
|---|---|---|
| 用户 | `admin.users.read` | 创建、编辑、停用与恢复、删除、剪枝邀请树 |
| 媒体账号 | `admin.media.read` | 管理媒体账号、审核认领 |
| 媒体服务与推流 | `admin.config.media.read` | 管理媒体服务器、节点与线路 |
| 媒体库规则 | `admin.libraries.read` | 配置媒体库规则 |
| 访问分组 | `admin.groups.read` | 管理分组与成员 |
| 求片 | `admin.wish.read` | 处理求片 |
| 商店 | `admin.shop.read` | 管理商品、礼品卡与优惠券;查看礼品卡号(`admin.shop.reveal`,高风险) |
| 积分 / 红包 / 签到 | `admin.points.read`、`admin.redpacket.read`、`admin.checkin.read` | 调整积分(高风险)、发放红包与改红包规则、改签到规则 |
| 通知与 Bot | `admin.notify.read` | 管理 Bot、配置 Bot 准入 |
| 计划任务 | `admin.scheduler.read` | 启停、编辑、立即运行 |
| 系统配置 | `admin.config.read` | 发布业务配置(高风险) |

共 21 项可授予写权限。纯超管、不可授予的权限不变(管理员管理、API Key、引导配置、红包铸造、签到奖励上限、对账终结、宿主机文件写入)。授权弹窗支持搜索、按业务域折叠、整组开关、高风险提示,并在底栏显示相对原来的增减。

## 菜单渲染规则

菜单由 `/auth/me` 返回的权限点与 `/app/features` 的功能开关共同生成。

1. 每个菜单项声明所需的**读权限**；缺失则不渲染。
2. 页面内的写操作声明所需的**写权限**；缺失则隐藏或置灰。
3. 前端**不**复制“角色 × 层级”矩阵；只对后端下发的权限点做查表。
4. 隐藏菜单不是授权，所有接口仍由后端校验，返回 401 / 403 / 409 / 429 时前端按[通用反馈](/states-errors)呈现。

## 账号状态与功能门控

| 状态 | 来源 | 影响 |
|---|---|---|
| 用户被禁用 | 管理员在后台禁用 | **唯一全站阻断**：会话撤销、拒绝登录、Bot 拒绝、Emby 连带禁用 |
| 媒体账号 `active` | — | 全部功能可用 |
| 媒体账号 `expired` | 到期（宽限期内） | Emby 播放、改密、在线设备不可用；**续期、线路、积分、商店、求片仍可用** |
| 媒体账号 `suspended` | 管理员单独停用 | 同上；续期合法但不解除停用 |
| 媒体账号 `purging` / `purged` | 宽限期满后清除 | 不可续期；提示重新开通或认领 |

“停用”与生命周期状态是**并列的两枚徽标**，不是第五种生命周期值。

## 管理边界

| 操作 | admin | super_admin |
|---|---|---|
| 查看用户目录与详情 | 有读权限即可；**看不到超管** | 全部 |
| 禁用 / 恢复用户 | 需被授予 `admin.users.disable`;仅普通用户 | 除自己与其他超管外 |
| 重置密码 | 需被授予 `admin.users.update`;仅普通用户 | 除超管外 |
| 删除（软删）用户 | 需被授予 `admin.users.delete`;仅普通用户 | 不可删自己与超管 |
| 修改角色（user ↔ admin） | 否 | 是；自己与超管不可改 |
| 修改用户层级 | 通过受控资源与版本契约 | 是 |
| 剪枝邀请树与回滚 | 需被授予 `admin.users.prune` | 是（仅作用于普通用户,管理员与超管豁免） |
| API Key 管理、引导配置查看 | 否 | 是 |
| 宿主机文件：浏览、下载 | 是 | 是 |
| 宿主机文件：新建、重命名、删除 | 否 | 是 |
| 对账差异终结 | 否 | 是 |
| 积分:调整、查看他人账本与系统账户 | `admin.points.adjust` / `admin.points.read` | 是 |
| 签到:查看与修改规则、默认区间 | `admin.checkin.read` / `admin.checkin.write` | 是;奖励上限只有超管能改(`super.checkin.ceiling`) |
| 红包:发行、作废、查看全部 | `admin.redpacket.write` / `admin.redpacket.read` | 是;可铸造(`super.redpacket.mint`) |
| 红包:开关、发送范围、有效期、手续费、额度 | `admin.redpacket.config` | 是 |

## 通用交互约定

| 场景 | 约定 |
|---|---|
| 局部更新 | 提交携带 `expectedVersion`；冲突返回 409，提示“数据已被修改，请刷新” |
| 密钥类字段 | 只显示“已设置”；操作为明确的“替换”或“清除”，绝不回显明文 |
| 一次性明文（API Key） | 创建后仅显示一次，需勾选“我已保存”才能关闭 |
| 危险操作 | 确认弹窗说明影响范围；不可逆的需输入对象名确认 |
| 加载、空、错误 | 每个列表与详情都有骨架屏、空状态与带重试的错误态 |
