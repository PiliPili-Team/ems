# P12 幸运中心

<span class="badge-built">地基已实现</span> 幸运中心是三类玩法(魔法奖、彩票、小游戏)共用的地基:资金、玩家保护、公平与审计、抽奖券。具体玩法由后续变更交付;本页描述所有玩法必须遵守的规则。

## 资金模型

| 账户 | 角色 | 说明 |
|---|---|---|
| 用户 | 玩家 | 余额 ≥ 0 |
| 系统账户 0「庄家」 | 魔法奖、小游戏、彩票低等级固定奖的资金来源与收款方 | 余额 ≥ 0;仅超管可注资 |
| 系统账户 1「托管」 | 未开奖期次的彩票销售额、滚存奖池、用户发起抽奖的出资 | 余额 ≥ 0;按**用途**(彩票销售、彩票奖池、抽奖出资)分别记明细并逐用途对账 |

任何积分移动都是总量不变的两条分录;**不存在“系统凭空发奖”**。庄家余额不足时,需要它出钱的奖励不会发生,庄家不会为负。唯一的增发是超管注资,必须写原因与审计。

对账覆盖庄家与托管:用户余额之和 + 庄家 + 托管 = 历史净入账总和,且托管余额 = 各用途明细之和。

## 庄家保护

- 可用额度 = 庄家余额(不含托管)。单局最大可能赔付 ≤ `maxPayoutShare`(默认 5%)× 可用额度;可用额度低于 `minBankroll`(默认 2000)时,所有需要庄家兑付的玩法暂停接单,提示“暂不开放”,不扣款。
- 新站点庄家余额为 0,因此在管理员注资前魔法奖与小游戏全部处于“暂不开放”,这是有意的保守默认。
- 管理端在庄家低于阈值时显示告警。

## 玩家保护

| 能力 | 行为 |
|---|---|
| 全站默认关闭 | `lucky.enabled` 总开关与魔法奖、彩票、小游戏三个分类开关默认全关;总开关关闭时 `/lucky` 与 `/lucky/*` 返回 404;进行中的局不受开关影响,照常结算 |
| 每日净亏损上限 | 站点默认 1000(0 = 不限),按站点时区自然日;净亏损 = 当日消耗 − 当日奖金的正部分;达到后拒绝新的消耗,进行中的局可结束 |
| 自设上限 | 玩家可设更低上限;调低立即生效,调高或取消延迟 24 小时,管理员不能替玩家修改 |
| 冷静期 | 24 小时或 7 天,期间拒绝所有消耗型操作;只能申请提前结束,24 小时后生效;不能缩短、管理员不能取消 |
| 频率 | 每用户每秒最多 2 次写请求,超出 429 |

固定错误码:`lucky_unavailable`(庄家暂不开放)、`lucky_daily_loss`、`lucky_cooling_off`、`lucky_quota`、`insufficient_tickets`,以及既有的 `INSUFFICIENT_POINTS`、`USER_DISABLED`。被禁用的用户被全站阻断。

## 公平与审计

- 所有随机来自操作系统密码学随机数,离散抽取用拒绝采样消除偏差;结果先于动画写入局记录,刷新页面不会改变结果。
- **局记录**只增不改:玩法、玩家、规则版本、下注内容、结果、赔付、时间;玩家看自己的,管理员按玩法、玩家、时间检索。
- **规则版本化**:任何会改变概率、赔率或规则的修改都生成新版本并写审计,进行中的局沿用开局版本。
- **理论返还率(RTP)公示**,管理端显示近 7/30 天实际返还率与样本量;样本 ≥ 2000 局且偏差 > 5 个百分点时告警。
- 诚实声明:超管与运维能读写数据库,这套机制证明的是“规则公开且不被日常运营随意改动”,**不是**对站点所有者的密码学约束,界面不宣称“不可篡改”。

## 抽奖券

- 每用户一个整数余额 + 只增不改的券流水(来源、批次、可选过期时间)。消耗按到期时间先到先用;过期在读取时惰性结算并写“过期”流水。
- 来源(数值):管理员发放 1、魔法奖奖品 2、活动奖励 3、抽奖奖品 4、(预留)商店 5、签到 6、红包 7、消耗 8、过期 9。统一的发券入口由活动奖励与抽奖奖品复用,不得另建第二套券账本。
- 管理员按用户、层级或访问分组发放,每人 1–100 张,必填原因并写审计;非超管受每日发放额度限制(默认 1000 张/日)。同一幂等键重放返回首次结果,不重复发放。
- 券不可转赠、不可兑换成积分;只用于魔法奖,彩票叫“投注”。

## 魔法奖(盲盒)

玩家花积分(或抽奖券)抽一次,按公示的概率得到积分、商店商品、抽奖券、管理员自定义奖品或“谢谢参与”。

| 项 | 规则 |
|---|---|
| 价格 | 每次默认 20 积分,管理员可配 1–10000;十连 = 10 次独立抽取,总价 10×单价,无折扣;每人每日上限默认 200 次 |
| 支付 | 有抽奖券先扣 1 张(先到期先用),否则扣单价积分(入庄家);十连逐次决定,确认弹窗显示“券 a 张 + 积分 b”;用券的抽取庄家不收款 |
| 原子性 | 一次请求(1 或 10 抽)在一个写事务内完成扣费、抽取、库存、发奖与记录;任何一步失败整体回滚,不会出现“扣了款没出奖”;同一幂等键重放返回首次结果 |
| 概率 | 以百万分之一(ppm)配置,启用奖品的权重和必须恰好 1,000,000 才能发布;稀有度只由概率决定:≥ 20% 普通、≥ 5% 稀有、≥ 1% 史诗、< 1% 传说 |
| 版本 | 草稿随意改,发布生成新版本(审计含前后值);抽取只用已发布版本,每次抽取记录版本号与当时的实际概率 |
| 可抽性 | 每次抽取在事务内先算可抽集合:已启用、库存 > 0、积分奖金额 ≤ 庄家余额的 5%、商店商品存在且未下架且当前可发放;集合内按权重归一化得到**实际概率**;集合为空时拒绝且不扣款 |
| 奖品种类 | 积分(1–100000)、商店 SKU、抽奖券(1–100 张,可设有效天数)、自定义(估值必填,生成待发放)、谢谢参与 |
| SKU 范围 | 开通卡、续期卡、VIP 卡、白名单卡、心愿点数;**不含**积分卡与邀请卡;可一键加入全部可用商品,之后新增的商品不会自动加入;发放与购买等价但不扣积分、不占库存、不计购买次数;卡类带“魔法奖”来源记录,心愿点数入账流水的引用为 `magic:<局号>` |
| 自定义奖品 | 抽中后进入待发放队列(`admin.lucky.fulfil`),玩家收到站内通知;管理员“标记已发放”(备注必填)或“作废”(原因必填,玩家收到通知,不自动退款) |
| 自动推荐 | 目标返还率(默认 90%,50%–99%):权重 ∝ 1/估值,缩放使各奖品对期望的贡献相等,剩余概率归“谢谢参与”(未包含时归估值最低者),取整后总和恰为 1,000,000;池子过大无法达标时按比例缩小并提示;结果只是草稿,不自动发布 |
| 公示 | 每个奖品的配置概率、当前实际概率、剩余库存、“暂不可抽中”及原因;页头理论返还率 = Σ(实际概率 × 估值) ÷ 单价 |
| 开箱动画 | 单抽 ≤ 3.5 秒:盲盒入场 → 晃动两次 → 开盖光束 → 卡牌升起翻开 → 稀有度光晕;十连依次翻牌(间隔 150 ms)、最稀有的最后高亮;可随时跳过;`prefers-reduced-motion` 只做淡入;低端设备降级为简化粒子;动画期间有文字状态区供读屏 |

固定错误码另含 `lucky_draw_limit`(今日抽取次数已达上限)与 `lucky_pool_empty`(暂无可抽奖品)。

页面:玩家 `/lucky/magic`(余额与价格、盲盒与单抽/十连、确认弹窗、概率公示、近期稀有获奖、我的抽取记录);管理 `/admin/lucky/magic`(标题行“设置”齿轮与“发布”、标签“奖品池”“待发放”“抽取记录”、行内概率编辑 ppm 与百分比双向、草稿差异与总和校验条、自动推荐)。

## 彩票(双色球 / 大乐透 / 排列三)

三个彩种每日一期,开奖时间按站点时区(默认双色球 21:00、大乐透 21:10、排列三 20:50),开奖前 10 分钟截止投注。每注默认 2 积分(1–100),每人每期每彩种默认最多 20 注(1–100)。总开关或彩种开关关闭后不再开新期,但已开售期次照常开奖结算。

| 彩种 | 选号(默认) | 总组合 | 一等奖概率 | 固定奖返还 |
|---|---|---|---|---|
| 双色球 | 红 5/15 + 蓝 1/6 | 18,018 | 1/18,018 | 65.22% |
| 大乐透 | 前 4/15 + 后 2/6 | 20,475 | 1/20,475 | 59.21% |
| 排列三 | 三位 0–9,直选/组选 | 1,000 | 直选 1/1000 | 90% |

- 号码范围可配(双色球 k∈[3,6]、N∈[k+3,33]、M∈[2,16];大乐透 k∈[3,5]、N∈[k+3,35]、m∈[1,2]、M∈[m+2,12];排列三固定),但一等奖概率不得高于 1/1000;范围与奖级只影响之后开售的期次,进行中的期次沿用开售时的快照。
- 保存规则时精确计算各奖级概率与固定奖返还;固定奖返还**高于**庄家分成(销售额减去奖池分成)时拒绝保存,管理页并列显示返还、分成与试算。
- 投注:手选或服务端机选(1/5/10 注),提交带幂等键,一次提交的全部注原子扣款进托管;截止后拒绝且不扣款。排列三组选拒绝三位全同。庄家低于 `minBankroll` 或单注最大固定奖超过 5% 庄家额度时拒绝接单。
- 资金:销售额 S 在开奖前存放于托管;结算时 ⌊S × 奖池分成%⌋ 留在该彩种滚存奖池,其余划给庄家;一等奖由奖池按中奖注数均分(取整、余数留池),无人中奖整体滚存;低等级固定奖由庄家支付,庄家不足时按可用额度等比缩减并记录缩减系数、管理端告警。
- 提交—揭示:开售时生成 32 字节种子并存密封,公布 `SHA-256("ems-lottery/v1" · 彩种 · 期号 · 种子)`;开奖时用 `HMAC-SHA256(种子, "ems-lottery/v1" · 彩种 · 期号 · 计数器)` 作为确定性字节流,经拒绝采样做部分 Fisher–Yates。开奖后公布种子,页面提供承诺、种子、号码与复算脚本;界面如实说明种子在开售期间由服务端保管。
- 结算自动入账无需领奖:分批(500 注)幂等处理,每注记一条局记录;中断后继续;中奖用户收到站内通知;一等奖在彩票页显示打码用户名播报。每注以 `(期次, 投注)` 作为结算键,状态转移用版本号比较交换,任务重跑不会重复入账。
- 预计频率:近 14 日至少 7 期时显示 `1 ÷(平均每期注数 × 一等奖概率)` 期;样本不足不显示。
- 计划任务:`lottery.open_draw`(确保有开售期)、`lottery.draw`(到点开奖)、`lottery.settle`(分批结算),默认每分钟执行,缺跑后按顺序补跑,开奖号码仍由预先承诺的种子决定。
- 管理端「注入奖池」仅超管,把庄家积分转入托管奖池(不铸币),写审计;排列三无奖池。
- 固定错误码:`lottery_closed`(本期已截止)、`lottery_line_limit`(每期注数上限),以及既有的 `lucky_unavailable`、`lucky_daily_loss`、`lucky_cooling_off`、`INSUFFICIENT_POINTS`。
- 页面:玩家 `/lucky/lottery`(三彩种标签、选号/机选、注单与合计、截止倒计时、奖池、赔率表、预计频率、开奖历史、我的投注、验证面板);管理 `/admin/lucky/lottery`(每彩种开关与规则、即时概率与返还试算、当期与历史期次、缩减告警、注入奖池)。只读管理员可看,写需 `admin.lucky.write`。
