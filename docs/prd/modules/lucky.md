# P12 幸运中心

<span class="badge-built">地基已实现</span> 幸运中心是三类玩法(魔法奖、彩票、小游戏)共用的地基:资金、玩家保护、公平与审计、抽奖券。具体玩法由后续变更交付;本页描述所有玩法必须遵守的规则。

## 资金模型

| 账户 | 角色 | 说明 |
|---|---|---|
| 用户 | 玩家 | 余额 ≥ 0 |
| 系统账户 0「庄家」 | 魔法奖、小游戏、彩票低等级固定奖的资金来源与收款方 | 余额 ≥ 0;仅超管可注资 |
| 系统账户 1「托管」 | 未开奖期次的彩票销售额、滚存奖池、用户发起抽奖的出资 | 余额 ≥ 0;按**用途**(彩票销售、彩票奖池、抽奖出资)分别记明细并逐用途对账 |

任何积分移动都是总量不变的两条分录;**不存在“系统凭空发奖”**。庄家余额不足时,需要它出钱的奖励不会发生,庄家不会为负。唯一的增发是超管注资,必须写原因与审计。

对账覆盖庄家与托管:用户余额之和 + 庄家 + 托管 = 历史净入账总和,且托管余额 = 各用途明细之和。

## 庄家保护

- 可用额度 = 庄家余额(不含托管)。单局最大可能赔付 ≤ `maxPayoutShare`(默认 5%)× 可用额度;可用额度低于 `minBankroll`(默认 2000)时,所有需要庄家兑付的玩法暂停接单,提示“暂不开放”,不扣款。
- 新站点庄家余额为 0,因此在管理员注资前魔法奖与小游戏全部处于“暂不开放”,这是有意的保守默认。
- 管理端在庄家低于阈值时显示告警。

## 玩家保护

| 能力 | 行为 |
|---|---|
| 全站默认关闭 | `lucky.enabled` 总开关与魔法奖、彩票、小游戏三个分类开关默认全关;总开关关闭时 `/lucky` 与 `/lucky/*` 返回 404;进行中的局不受开关影响,照常结算 |
| 每日净亏损上限 | 站点默认 1000(0 = 不限),按站点时区自然日;净亏损 = 当日消耗 − 当日奖金的正部分;达到后拒绝新的消耗,进行中的局可结束 |
| 自设上限 | 玩家可设更低上限;调低立即生效,调高或取消延迟 24 小时,管理员不能替玩家修改 |
| 冷静期 | 24 小时或 7 天,期间拒绝所有消耗型操作;只能申请提前结束,24 小时后生效;不能缩短、管理员不能取消 |
| 频率 | 每用户每秒最多 2 次写请求,超出 429 |

固定错误码:`lucky_unavailable`(庄家暂不开放)、`lucky_daily_loss`、`lucky_cooling_off`、`lucky_quota`、`insufficient_tickets`,以及既有的 `INSUFFICIENT_POINTS`、`USER_DISABLED`。被禁用的用户被全站阻断。

## 公平与审计

- 所有随机来自操作系统密码学随机数,离散抽取用拒绝采样消除偏差;结果先于动画写入局记录,刷新页面不会改变结果。
- **局记录**只增不改:玩法、玩家、规则版本、下注内容、结果、赔付、时间;玩家看自己的,管理员按玩法、玩家、时间检索。
- **规则版本化**:任何会改变概率、赔率或规则的修改都生成新版本并写审计,进行中的局沿用开局版本。
- **理论返还率(RTP)公示**,管理端显示近 7/30 天实际返还率与样本量;样本 ≥ 2000 局且偏差 > 5 个百分点时告警。
- 诚实声明:超管与运维能读写数据库,这套机制证明的是“规则公开且不被日常运营随意改动”,**不是**对站点所有者的密码学约束,界面不宣称“不可篡改”。

## 抽奖券

- 每用户一个整数余额 + 只增不改的券流水(来源、批次、可选过期时间)。消耗按到期时间先到先用;过期在读取时惰性结算并写“过期”流水。
- 来源(数值):管理员发放 1、魔法奖奖品 2、活动奖励 3、抽奖奖品 4、(预留)商店 5、签到 6、红包 7、消耗 8、过期 9。统一的发券入口由活动奖励与抽奖奖品复用,不得另建第二套券账本。
- 管理员按用户、层级或访问分组发放,每人 1–100 张,必填原因并写审计;非超管受每日发放额度限制(默认 1000 张/日)。同一幂等键重放返回首次结果,不重复发放。
- 券不可转赠、不可兑换成积分;只用于魔法奖,彩票叫“投注”。

## 页面

| 页面 | 内容 |
|---|---|
| `/lucky` | 入口:只列出已开启的玩法(尚无页面的显示“即将开放”)、抽奖券余额、今日净亏损与上限、庄家是否开放、冷静期提示 |
| `/lucky/history` | 我的记录:对局、抽奖券流水、限额与冷静期三个标签 |
| `/admin/lucky` | 总览:庄家余额与近 7 天盈亏、托管明细、各玩法 7/30 天返还率与告警;庄家注资(仅超管)、全局设置与发放抽奖券(`admin.lucky.write`)、对局检索 |

会员端与管理端页面互不放跳转链接。

## 权限与角色

| 权限 | 默认持有 | 说明 |
|---|---|---|
| `lucky.self` | 所有未禁用用户 | 入口、记录、自设限额与冷静期 |
| `admin.lucky.read` | 管理员 | 总览、设置与对局只读 |
| `admin.lucky.write` | 可授予 | 全局设置、发放抽奖券、玩法配置 |
| `admin.lucky.fulfil` | 可授予 | 处理自定义奖品(随魔法奖变更交付接口) |
| `super.lucky.fund` | 仅超管 | 庄家注资,不可授予 |

## 依赖接口

`/lucky*`、`/admin/lucky*`、`/auth/me`(功能开关 `luckyEnabled`)、`/app/features`、`/points/ledger`。
