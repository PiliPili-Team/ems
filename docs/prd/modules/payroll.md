# P15 薪资

<span class="badge-built">已实现</span> 管理员与超管按月领取薪资:薪资 = 底薪 + 绩效,绩效 = ⌈绩效基数 × 完成率⌉。任务由超管配置,进度自动计数或手动登记;每月 1 日 00:10(站点时区)结算上月,生成工资单,管理员在领取期内领取,由系统账户支付。

## 我的薪资 `/payroll`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 本月概况 | 纯平卡片:完成率圆环、本月截至目前的薪资(大号数字)、「底薪 + 绩效」拆分、结算说明 | 只读,实时计算 |
| 本月任务 | 一张纯平列表:任务名、进度来源(自动计数的统计内容或「由超管登记」)、权重占比、进度条与「当前 / 目标」;完成的任务显示对勾(弹入,减少动效时不动) | 只读 |
| 工资单 | 自动填充卡片(每列至少 18rem):月份、完成率、总额、拆分、状态徽标(待领取 / 已领取 / 已作废)、领取截止或领取时间 | 「领取」一次领完,金额从 0 滚动到总额并提示新余额;「明细」打开右侧抽屉,列出结算时冻结的任务进度 |

超管与管理员一样领薪:结算时也为超管生成工资单,任务可指派给超管,薪资入超管个人账户(由系统账户支付)。没有任务时显示「本月没有任务」与「只发底薪」;没有工资单时显示空状态。

## 薪资管理 `/super/payroll`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 任务 | 页头分段控件(任务 / 进度 / 工资单)在中轴,右栏是月份选择(往前 12 个月、往后 3 个月)、设置齿轮与「新建任务」;任务是自动填充卡片:名称、统计内容、适用对象(全体管理员或某位管理员)、目标与权重 | 新建与编辑用右侧抽屉;删除先确认;过去的月份只读 |
| 进度 | 每位管理员一张卡片:完成率圆环、用户名与 UID、当前薪资,下面逐项任务进度 | 手动任务行内「登记」,右侧抽屉填写进度与备注 |
| 工资单 | 当月工资单列表:管理员、完成率、总额、状态 | 只读 |
| 薪资设置 | 齿轮打开右侧抽屉:底薪(默认 200)、绩效基数(默认 100)、领取期(默认 30 天) | 按版本保存;只影响之后结算的月份 |

**规则**:

- 完成率 = Σ(min(进度 / 目标, 1) × 权重) / Σ权重,以基点向下取整;没有任务的月份完成率为 0,只发底薪。
- 进度来源是数值枚举:1 自动计数、2 手动登记。自动计数按审计动作统计该管理员当月次数,统计内容也是数值枚举:1 回复工单、2 关闭工单、3 处理心愿、4 审核媒体认领、5 发送邮件。手动登记写审计。
- 任务可为当月及之后 3 个月创建;月份结算后任务与进度冻结(409 `MONTH_CLOSED`)。
- 结算由计划任务 `payroll.close`(每月 1 日 00:10)执行,服务启动时也会补跑;错过的月份逐月补结算,每人每月只有一张工资单。只为结算时仍为管理员且未停用的账号出单;月中任命按全额。
- 领取在一个事务内完成:系统账户(编号 0)先生成再支付,账本来源「薪资」29;同一工资单并发领取只入账一次;超过领取期作废(409 `CLAIM_EXPIRED`)。单人单月不超过底薪 + 绩效基数。
- 审计模块「薪资」(18):`payroll.task.create/update/delete`、`payroll.progress`、`payroll.close`、`payroll.claim`、`payroll.settings`。

权限:`payroll.self`(管理员与超管;普通用户、VIP、白名单 403)、`super.payroll`(仅超管,不可授予)。
