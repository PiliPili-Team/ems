# A4 推流节点与线路

<span class="badge-built">已实现</span> 节点、线路、类型 schema、试匹配、节点健康检查均已实现。节点与线路是两个独立页面(`/admin/stream/nodes`、`/admin/stream/lines`),且只在部署具备前端网关时存在(见[部署模式](#部署模式))。线路的接入范围由“层级 + 自定义分组”组成,不再逐个指定用户(见 [A8 访问分组](/modules/admin-groups))。

## 概念

- **节点**：一个具体的数据来源或转发目标，有类型和匹配规则。
- **线路**：用户选择的入口，包含按顺序排列的一组节点。
- 两层路由：线路选择（用户可见，可选）× 节点正则匹配（线路内按顺序，用户无感）。

## 节点管理

| 子功能 | 展示 | 交互 |
|---|---|---|
| 节点卡片列表 | 类型徽标、匹配方式与表达式、线路内顺序、启停开关、健康状态、远程节点标记 | 开关即时保存；点击编辑 |
| 选择类型 | 新建时用下拉选择类型(磁盘、OpenList、DirectLink、WebDav、Google Drive、StreamRelay),选项来自后端 `node-types`,文案走多语言 | 选中后进入对应表单;**创建后类型不可更改**,编辑时只读显示并说明“更换类型请删除后重建”,后端对变更类型的请求返回 422 |
| 类型化表单 | **字段由后端 `node-types` schema 驱动**，未加载前显示骨架并禁用 | 密钥类字段显示“已设置”；前端不硬编码字段 |
| 匹配规则 | 匹配方式（regex / prefix / any）+ 表达式输入框 | 前端实时试编译正则；“试匹配”输入样例路径调用后端，显示命中与否（后端为准） |
| 健康状态 | 徽标:正常 / 较慢 / 不可达 / 待检测 / 无需检测,正常与较慢显示延迟,不可达显示失败原因;悬停显示最近检查时间 | 前端枢纽每 15 秒探测一次 StreamRelay 节点的 `/healthz`;连续 2 次失败才判为不可达,1 次成功即恢复;状态变化写审计事件。**只展示,不改变路由选择**;状态只存内存,重启后重新探测。其他类型的节点显示“无需检测” |
| 保存 | — | 热生效提示；失败显示字段级错误 |
| 删除 | 行菜单 | 被线路引用时后端拒绝并列出线路 |

## 线路管理

| 子功能 | 展示 | 交互 |
|---|---|---|
| 线路列表 | 名称、入口地址、接入范围摘要（`不限` / `N 层级 + M 分组`）、主线路星标、节点数、启停 | 开关即时保存 |
| 编辑线路 | 基本信息 + [接入范围编辑器](/modules/admin-media#接入范围编辑器) + 节点选择 | 节点多选；**拖拽排序即优先级** |
| 保存节点顺序 | 独立保存按钮 | 提交完整有序列表 |
| 主线路 | 星标 | 至少需要一条启用的主线路；取消最后一条时拒绝 |
| 延迟面板 | 节点 × 线路延迟矩阵 | 30 秒自动刷新 |

节点页每 15 秒刷新一次,与探测节奏一致。

## 角色差异

| 能力 | admin | super_admin |
|---|---|---|
| 查看 | 有 `admin.config.media` | 是 |
| 创建、编辑、删除 | 有对应写权限 | 是 |

普通用户只在 [线路](/modules/lines) 页看到结果，不接触节点。

## 状态与边界

- 正则无效：前端试编译失败时阻止保存。
- 试匹配后端不可用：显示“无法验证”，允许保存但警告。
- 节点类型 schema 加载失败：表单不可用，提供重试。

## 依赖接口

`/admin/stream/nodes*`(响应含 `health`)、`/admin/stream/node-types`、`/admin/stream/nodes/test-pattern`、`/admin/stream/lines*`、`/system/capabilities`。

## 部署模式

一个 EMS 进程由 `EMS_DEPLOY_MODE` 决定做什么,后端据此推导能力并在 `GET /system/capabilities` 返回,前端据此显示或隐藏页面;后端对缺失的能力根本不挂载路由(404),不只是界面隐藏。

| 模式 | 管理 API 与页面 | 前端网关(拦截并路由) | 出流 |
|---|---|---|---|
| `management` 仅管理 | 有 | 无 | 无 |
| `frontend_hub` 前端枢纽 | 有 | 有 | 无 |
| `backend_hub` 后端枢纽 | 无(仅 `/healthz` 与出流) | 无 | 有 |
| `all_in_one` 一体(缺省) | 有 | 有 | 有 |

- 节点与线路页面、`/lines` 页面及其 API 只在具备前端网关的模式(`frontend_hub`、`all_in_one`)存在;`management` 下全部隐藏。
- 后端枢纽手工配置、无状态:没有用户库,只信任前端枢纽签发的播放授权。授权整体加密并认证,里面带数字 UID、层级枚举和有长度上限的扩展位;UID 与层级不会以明文出现在 URL 中。
- 网关链在选路前有一个默认放行的 `Guard` 阶段,为日后的 WAF 预留;本阶段不含任何 WAF 规则。
