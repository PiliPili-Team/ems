# A1 用户管理与邀请树

用户管理 <span class="badge-built">已实现</span>；邀请树与链式封禁 <span class="badge-planned">待实现</span>，**同一阶段交付**：查看（邀请树）与处置（链式封禁、回滚）不拆开，避免出现只能看不能处置或相反的半成品。运营仪表盘见 [P2](/modules/home-dashboard)。

## 用户管理 `/user`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 用户列表 | 表格：头像与用户名、角色、层级、积分、媒体账号数、邀请人、状态、注册时间 | 服务端分页；按角色、层级、状态、关键词筛选；列排序 |
| 详情抽屉 | 资料、邀请树位置、账本摘要、媒体账号、审计摘要 | 点击行打开；标签页切换 |
| 禁用 / 恢复 | 状态开关 | 确认弹窗说明连带效果：会话撤销、Bot 拒绝、Emby 连带禁用 |
| 重置密码 | 行菜单“重置密码” | 输入新密码并确认 |
| 修改资料与层级 | 编辑表单 | 提交带 `expectedVersion`；冲突提示刷新 |
| 删除（软删） | 行菜单“删除” | 红色确认，需输入用户名 |
| 重置媒体账号密码 | 抽屉内按钮 | 需 `admin.media.write` |
| 角色管理 | 抽屉内“设为管理员 / 取消管理员” | 仅超管可见 |

**边界规则的展示**：

- admin 的列表中**不出现超级管理员**；查询超管返回 404 风格的“不存在”。
- admin 对管理员的行不显示写操作。
- 任何人对自己的行不显示禁用、删除、改角色。

## 邀请树 `/admin/users/:id/tree`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 祖先链 | 从根到该用户的面包屑式链路 | 点击跳转到对应用户的树 |
| 后代树 | 可折叠树形列表，节点显示状态与角色 | 展开 / 折叠；点击节点进入详情 |
| 统计 | 后代总数、已禁用数 | 只读 |

## 链式封禁（仅超管）

| 步骤 | 展示 | 交互 |
|---|---|---|
| 预览 | 受影响的后代数量与名单；管理员与超管被标记为“豁免” | 点击“链式封禁”先调用预览，不执行 |
| 确认 | 红色弹窗：将禁用 N 人；需输入根用户名 | 确认后执行 |
| 结果 | “已封禁 N 人，全部会话失效”；Emby 联动显示“最终一致，处理中” | 可跳转封禁记录 |
| 回滚 | 封禁记录列表，每条有“回滚”按钮 | 二次确认；回滚后恢复该次封禁的用户 |

## 角色差异

| 能力 | admin | super_admin |
|---|---|---|
| 查看用户 | 看不到超管 | 全部 |
| 禁用、改密、删除 | 仅普通用户 | 除自己与超管外 |
| 改角色 | 否 | 是 |
| 邀请树查看 | 是 | 是 |
| 链式封禁与回滚 | 否 | 是 |

## 状态与边界

- 目标用户在操作中被他人修改：409，提示刷新。
- Emby 联动失败：封禁已生效，页面显示“联动重试中”，并链接到系统的任务队列。
- 空列表：显示筛选条件并提供“清除筛选”。

## 依赖接口

`/admin/users*`、`/admin/users/{id}/tree`、chain-ban 与 `chain-ban-actions`（planned）、`/super/admins`。
