# P1 认证与首次初始化

<span class="badge-built">已实现</span> 登录、初始化、服务状态；注册与 Telegram 登录需随后端补齐。

## 目的

让用户安全进入系统，并让运维人员在空库上完成首次配置。

## 子功能

### 登录 `/login`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 密码登录 | 左侧品牌与壁纸，右侧登录卡；窄屏单列 | 提交后成功进入原目标页；失败在表单内显示错误 |
| Passkey 登录 | 输入框支持自动填充提示 + “使用通行密钥”按钮 | 调起浏览器 WebAuthn；取消不报错；不支持的浏览器隐藏按钮 |
| Telegram 登录 | 仅当后端声明可用时显示 | 仅登录**已绑定**的账号，不会自动创建账号 |
| 注册入口 | 仅当后端声明开放注册时显示 | 填写邀请码（邀请制必填）、用户名、密码；成功后提示去登录 |
| 登录限流 | 表单顶部提示“请 N 分钟后重试” | 登录按钮倒计时禁用 |
| 语言与主题 | 右上角切换 | 未登录写本地；登录后同步到账号偏好 |
| 壁纸 | 后端决定来源（TMDB、Bing、静态） | 前端不判断来源；加载失败回退纯色背景 |

登录能力（是否开放注册、Passkey、Telegram）全部来自公开的 `/app/bootstrap`，前端不硬编码。

### 首次初始化 `/initialize`

仅当后端报告“未初始化”时可访问；完成后该路由返回 404。

| 步骤 | 展示 | 交互 |
|---|---|---|
| 1 创建超级管理员 | 用户名、密码、确认密码 | 密码强度提示；提交后获得引导会话 |
| 2 API Key | 一次性明文 + 复制按钮 | 勾选“我已保存”后才能下一步 |
| 3 媒体服务器 | 地址与 API Key 表单 | “测试连接”即时反馈；可稍后配置 |
| 4 线路与节点 | 类型化表单 + 匹配测试 | 可跳过；至少需要一条启用的主线路才能完成 |
| 完成 | 成功页 | 跳转登录 |

步骤进度来自后端；刷新页面可恢复到当前步骤。

### 服务状态 `/service-status`

| 展示 | 交互 |
|---|---|
| 服务是否就绪、版本、关键依赖健康 | 自动刷新；后端不可达时显示明确的离线说明与重试 |

## 角色差异

| 角色 | 差异 |
|---|---|
| 匿名 | 仅 `/login`、`/initialize`（条件）、`/service-status` |
| 已登录 | 访问 `/login` 自动跳转首页 |
| 被禁用用户 | 登录返回禁用状态，页面显示“账号已被禁用，请联系管理员”，不创建新会话 |

## 状态与边界

- 会话过期：下一次请求返回 401，保存当前路径并跳转登录，登录后返回。
- 初始化被他人抢先完成：当前步骤提交返回冲突，提示“系统已初始化”并跳转登录。
- 后端不可达：全局离线条，不清除本地会话。

## 依赖接口

`/app/bootstrap`、`/auth/login`、`/auth/passkey/auth/*`、`/auth/telegram/miniapp`、`/auth/register`（planned）、`/setup/*`。
