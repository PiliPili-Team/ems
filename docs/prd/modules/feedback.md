# P11 工单与反馈

<span class="badge-built">已实现</span> 用户可提交工单并与管理员多轮对话；提交收取可退还积分，长期无活动自动关闭。

## 用户端 `/feedback`

| 能力 | 行为 |
|---|---|
| 列表 | 状态筛选、分页、未读标记；可同时存在多张工单 |
| 新建 | 仅标题必填（1–120 字）；正文与最多 3 张图片可选；对话框显示费用与当前余额 |
| 费用 | 默认 10 积分，可在配置域 `feedback` 调整（0 = 免费）；余额不足不创建工单 |
| 详情 | 聊天式时间线、联系方式只读卡、追加回复/图片、关闭、关闭后 14 天内重开（最多 3 次）、一次性 1–5 星评价 |
| 联系方式 | 面板 UID 必有；Telegram 取提交时绑定，未绑定显示“未绑定”；用户不可填写 |
| 系统消息 | 自动关闭、退费、重开由 UID 0“系统”居中显示，按界面语言渲染 |

## 管理端 `/admin/feedback`

| 能力 | 行为 |
|---|---|
| 列表 | 状态、等待方、负责人（全部/未分配/我的）、优先级、标题或 UID、日期筛选；按最近活动排序；摘要条含待回复数、平均首次响应、近 30 天评分 |
| 详情 | 完整对话、实时联系方式、内部备注（黄色底，仅管理员可见）、公开回复、关闭/重开、优先级、认领/取消、全额退款 |
| 权限 | 读 `admin.feedback.read`；写 `admin.feedback.write`；退款 `admin.feedback.refund`。管理员默认只读，写权限逐项授予 |
| 角标 | 侧栏显示待管理员回复数；仅页面可见时每 60 秒刷新 |
| 退款 | 全额一次，创建后 90 天内；系统账户不足返回 `house_insufficient`，不铸币 |

## 自动关闭

- 计划任务 `feedback.auto_close` 每小时运行；参数 `autoCloseDays`（7–365，默认 30）控制无公开消息关闭天数。
- 内部备注不重置计时。
- 管理员从未公开回复时同事务全额退费；系统账户不足则关闭成功并标记待退款，下一轮重试。
- 重复执行幂等，已关闭工单不追加第二条系统消息。

## 附件

PNG/JPEG/WebP，单张 ≤ 2 MB，每条 ≤ 3 张；服务端归一化为 WebP（最长边 2048），仅工单所有者与有读权限的管理员可读。关闭 180 天后清理二进制，消息保留并显示“附件已清理”。

## 依赖接口

`/feedback*`、`/admin/feedback*`、`/auth/me`、`/points/balance`、`/admin/points/system`。
