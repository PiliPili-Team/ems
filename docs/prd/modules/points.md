# P5 积分与红包

<span class="badge-planned">待实现</span> 后端接口全部为 planned。整体受 `points.enabled` 功能开关控制，关闭时菜单隐藏、直接访问为 404。

## 积分中心 `/points`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 余额头部 | 大号余额数字、今日签到状态 | 只读 |
| 每日签到 | 签到按钮；已签到时置灰并显示“明日再来” | 点击后弹出结果动画，展示随机获得的积分；余额数字滚动更新 |
| 签到日历 | 当月日历，已签日期打勾 | 只读 |
| 账本流水 | 时间线：来源图标（签到、红包、兑换、调整）、变动值、变动后余额 | 分页或无限滚动；按来源筛选 |
| 前往商店 | 余额不足引导 | 按钮跳转 `/shop` |

**不变式**：余额永不为负；账本只增不改；所有变动可溯源。

## 红包 `/points/red-packets`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 可领列表 | 卡片：类型标签（拼手气 / 专属）、剩余次数与金额、发起人 | 点击“领取”；成功后弹出所得积分，卡片更新 |
| 领取状态 | 已领取、已领完、已过期、专属他人 | 对应状态置灰并说明原因 |
| 我的领取记录 | 列表：红包、金额、时间 | 分页 |
| 我发的红包 | 列表：总额、已领进度条、状态 | 展开查看领取明细 |
| 发红包 | “发红包”按钮：**默认只有管理员能发行**；仅当管理员在系统设置中打开“允许用户发红包”开关时，普通用户才显示此按钮 | 表单：类型（拼手气 / 专属）、总额、份数、分配方式（均分 / 随机）；专属需选择目标用户和金额；提交前显示扣减后的余额 |

## 角色差异

| 角色 | 差异 |
|---|---|
| user（任一层级） | 全部个人功能；发红包受“允许用户发红包”开关控制，默认关闭 |
| admin / super_admin | 个人功能同用户；发行与管理见 [商店、红包与积分运营](/modules/admin-commerce) |

## 状态与边界

- 重复点击签到：幂等，返回“今日已签到”。
- 红包被抢完：领取返回冲突，列表刷新为“已领完”。
- 余额不足发红包：按钮禁用并显示差额；后端返回的 `shortfall` 参数用于文案。
- 功能关闭：整页隐藏。

## 依赖接口

`/points/checkin`、`/points/balance`、`/points/ledger`、`/red-packets`、`/red-packets/claims`、`/red-packets/mine`、`/red-packets/mine-claims`。
