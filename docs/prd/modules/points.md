# P5 积分与红包

<span class="badge-built">已实现</span> 积分、签到、红包由后端三个独立模块提供:积分账本只有一个入账口;签到与红包都通过它入账,互相不含对方的规则。积分系统始终开启,因为它是签到、红包与商店的计价基础;`points` 配置域与 `points.enabled` 字段已删除,功能开关也不再下发 `pointsEnabled`。红包与签到只受各自开关控制。管理员页不再提供积分总开关。

## 积分中心 `/points`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 余额卡 | 大号余额;红包、商店入口 | 只读 |
| 每日签到 | 与余额卡等宽等高的卡片:今日奖励区间、签到按钮、当月日历 | 点击后显示获得的积分并就地更新余额;已签到置灰并显示“明天再来”;规则关闭或功能关闭时说明原因 |
| 积分时间线 | **最新在最上**,按日期分组,每条有来源图标与配色、时间、变动值(收入绿 `+`、支出红 `−`)与变动后余额 | 顶部分段 全部 / 收入 / 支出(默认**收入**),另有来源选择器;“加载更多”追加下一页 |

**不变式**:余额永不为负;账本只增不改;每条变动可溯源(来源 + 引用)。

## 红包 `/points/red-packets`

红包由两个独立选项描述:**受众**(所有人 / 指定分组 / 指定用户)与**分配方式**(均分 / 拼手气)。

| 子功能 | 展示 | 交互 |
|---|---|---|
| 可领列表 | 卡片:发行人、受众、分配方式、剩余积分与份数、进度条、到期时间 | “领取”;成功后提示所得,列表以后端为准刷新 |
| 口令领取 | 输入红包口令 | 领取 |
| 规则 | 有效期、手续费、退回说明(来自后端) | 只读 |
| 发红包 | 仅当后端 `capabilities.canSend` 为真时显示 | 见下 |

**发红包**(用户):只能发“指定用户”红包,收件人用用户名搜索选择(最多 50 人,每人一份);输入金额后即时预览“你将支付 / 手续费 / 红包面额 / 到期退回说明”,公式只在后端。管理员可发三种受众,出资不扣个人积分,超管可铸造。

**手续费**:个人出资的红包从**输入金额内**扣除,默认 10%,范围 1%–50%,向上取整、最低 1;归系统账户;管理员发行与铸造免收。到期或作废时只退回未领的面额,**手续费不退**。

**过期**:默认 24 小时(1–168)。到期后系统在同一事务内把个人出资的未领面额退回发行人,管理员出资的未领部分销毁;领取时后端自行检查到期,不依赖任务是否已跑;功能关闭也照常处理,价值不会滞留。

## 红包记录 `/points/red-packets/history`

两个等宽标签 **我发的 | 我领的**,当前标签写入地址 `?tab=1|2`。

- **我发的**:输入金额 / 手续费 / 红包面额三栏等宽,领取进度条,状态徽标,到期后退回或销毁额;可展开查看领取明细;可按状态筛选。
- **我领的**:发行人、受众、状态、所得积分与时间。

## 角色差异

| 角色 | 差异 |
|---|---|
| user(任一层级) | 全部个人功能;发红包受 `redPacket.userSend` 的开关与范围控制,默认关闭 |
| admin / super_admin | 个人功能同用户;发行与管理见[商店、红包与积分运营](/modules/admin-commerce) |

## 状态与边界

- 重复点击签到:幂等,返回“今日已签到”(409)。
- 红包被领完或已到期:领取返回 409,列表刷新。
- 余额不足:发红包返回 `INSUFFICIENT_POINTS`。
- 功能关闭:整页隐藏,接口返回 404(`FEATURE_DISABLED`)。
- 同一出口地址每分钟最多 600 次写操作,超出返回 429 并带重试时间。

## 依赖接口

`/points/ledger`、`/points/balance`、`/checkin`、`/checkin/status`、`/red-packets`(+`/capabilities`、`/quote`、`/recipients`、`/claims`、`/{id}/claim`、`/mine`、`/mine/{id}/claims`、`/mine-claims`)。所有类型、状态、来源均为数值枚举,编号为整数。
