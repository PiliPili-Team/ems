# A2 商店、红包与积分运营

<span class="badge-planned">待实现</span> 全部接口为 planned。

## 商品与码 `/admin/shop`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 商品列表 | 名称、类型（五类码）、价格、有效期、库存、上下架状态 | 开关上下架；点击编辑 |
| 新建 / 编辑商品 | 表单：类型、名称、价格、有效期、库存（无限 / 数量）、可见性规则 | 提交带版本；价格或库存修改立即生效 |
| 删除商品 | 行菜单 | 已有订单的商品只能下架，不能删除 |
| 码查询 | 搜索框：码串、订单号、用户 | 结果列表；点击进入溯源时间线 |
| 溯源时间线 | 生成 → 兑换（谁、何时）→ 使用（对谁）→ 作废 | 只读 |
| 作废码 | 未使用的码显示“作废” | 确认弹窗；已使用不可作废 |

## 红包管理 `/admin/red-packets`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 发行 | 表单：拼手气（总额、份数、均分 / 随机）或专属（目标用户、金额） | **发红包默认由管理员发行**；管理员发行不扣个人积分，超管有专门的“铸造”权限点 |
| 用户发红包开关 | 页面顶部开关“允许用户发红包”，附当前状态说明 | 切换需确认；关闭后用户端的“发红包”按钮立即隐藏，进行中的红包不受影响 |
| 历史列表 | 发行时间、类型、总额、领取进度条、状态 | 展开查看领取明细（谁、多少、何时） |
| 作废红包 | 进行中的红包显示“作废” | 确认；剩余金额按规则退回 |

## 积分调整与对账 `/admin/points`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 手动调整 | 选择用户、增减金额、原因（必填） | 表单旁**显示剩余调整额度**（来自 `adjust/limit`，含周期与已用）；超出额度时禁用提交并说明；**无需超管复核**，提交即生效；每次调整必写入账本与审计日志 |
| 对账 | 差异列表：用户、账本合计、余额、差值 | 点击进入该用户账本 |
| 终结差异 | 每条差异的“修复并终结”按钮 | **仅超管**；弹窗说明将写入的修正分录 |

## 角色差异

| 能力 | admin | super_admin |
|---|---|---|
| 商品与码管理、作废 | 是 | 是 |
| 红包发行与作废 | 是 | 是；含铸造 |
| 积分调整 | 有 `admin.points.adjust` 权限 | 是 |
| 对账查看 | 是 | 是 |
| 对账差异终结 | 否 | 是 |

## 状态与边界

- 调整导致余额为负：后端拒绝，提示“余额不足”。
- 商品被同时修改：409。
- 红包被并发领取时作废：以后端结果为准，列表刷新。

## 依赖接口

`/admin/shop/*`、`/admin/points/red-packets*`、`/admin/points/adjust*`、`/admin/points/reconcile*`。
