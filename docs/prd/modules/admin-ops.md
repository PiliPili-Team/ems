# A5 心愿管理、通知与计划任务

心愿管理 `/admin/wishes` 对持 `admin.wish.read` 的管理员开放;通知接口为 planned;计划任务接口已实现。

## 心愿管理 `/admin/wishes`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 心愿列表 | 桌面数据表:海报、影视名/年份/类型、可复制 TMDB ID、申请人、精确季/集范围、花费及来源、状态、时间;默认倒序 | 带计数的状态分段标签、类型与 UID 筛选,服务端每页 10 条;390px 窄屏为卡片 |
| 详情侧栏 | 完整影视简介、范围明细、花费的每日/已购拆分、备注与流转历史 | 点击行打开;只读管理员看到“仅查看” |
| 状态流转 | 待处理 → 进行中/已处理;进行中 → 已处理 | 持 `admin.wish.write` 者通过备注对话框操作,409 提示并刷新 |
| 过期条目 | 已过期心愿 | 持写权限者可重新激活;重新计算过期时间,不重复扣费或退款 |
| 心愿策略 | 常显概览卡、价格与封顶试算、每日发放(默认/等级/个人/分组)、基础设置 | 配置带版本保存需 `admin.config.write`;覆盖规则需 `admin.wish.write`;无改动不显示吸底保存栏;只读不显示编辑控件 |

## 通知与 Bot `/admin/notify`

| 子功能 | 展示 | 交互 |
|---|---|---|
| Bot 配置 | 列表：名称、状态；表单：Token、代理（可选） | Token 只显示“已设置”；“发送测试”直接发消息 |
| 订阅矩阵 | 行为会话（chatId），列为事件（每日 Top5、每周 Top5） | 勾选即保存 |
| 推送预览 | “预览 Top5”按钮 | 展示海报、文字与链接的推送样式 |
| Bot 群组准入 | 群组列表，规则 all / any | “探测”验证机器人在群内权限；保存后 10 分钟缓存内生效 |

## 计划任务 `/admin/scheduler`

| 子功能 | 展示 | 交互 |
|---|---|---|
| 任务卡片 | 名称、描述、默认 cron、当前 cron、下次运行、最近执行状态徽标、启停开关 | 开关即时保存 |
| 编辑 | cron 输入 + 人类可读预览（如“每天 19:00”）+ 参数表单 | 参数表单按任务 schema 渲染；非法 cron 阻止保存 |
| 手动触发 | “立即运行” | 返回运行编号，行内进度每数秒刷新（最长约 30 秒），之后转入历史 |
| 执行历史 | 表格：时间、状态、影响行数、耗时、错误摘要 | 按任务与状态筛选，分页 |
| 内置任务 | 只读展示类型 | 不可新增或删除 |

## 角色差异

| 能力 | admin | super_admin |
|---|---|---|
| 心愿管理 | 查看:默认;流转、重新激活和个人/分组发放规则:被授予 `admin.wish.write`;全局策略编辑:`admin.config.write` | 是 |
| 通知与 Bot | 有 `admin.notify.write`；群组准入需 `admin.bot.access` | 是 |
| 计划任务查看 | `admin.scheduler.read` | 是 |
| 计划任务启停、编辑、触发 | `admin.scheduler.write` | 是 |

## 状态与边界

- 任务运行中再次触发：后端拒绝，按钮显示“运行中”。
- Bot Token 无效：测试失败显示 Telegram 返回的原因。
- 任务租约超时：历史中标记“已回收”。

## 依赖接口

`/admin/wishes*`、`/admin/notify/*`、`/admin/bot*`、`/admin/scheduler/*`。
