# P7 求片

<span class="badge-built">已实现</span> 专页 `/wishes`、管理页 `/admin/wishes` 与策略卡片均已上线;求片编号为自增整数,状态为数值枚举(1 待处理、2 进行中、3 已处理、4 已过期)。

## 目的

用户向管理员提交想看的影片，并跟踪处理进度。需要用户拥有有效媒体账号。

## 子功能

| 子功能 | 展示 | 交互 |
|---|---|---|
| 提交求片 | 输入框：粘贴 TMDB 链接或 ID；也可从发现页详情的“求片”按钮带入(`?tmdb=&type=`) | 失焦自动解析，显示标题、海报、简介预览卡(接口不返回年份,故不显示);确认后提交 |
| 额度提示 | “今日剩余 N 次，将于 hh:mm 重置” | 数据取自后端额度接口；用完则按钮禁用并显示重置时间 |
| 重复检测 | 提交时若 30 天内已有同一条目，显示已有条目卡片 | 提供“查看已有求片”定位入口，不重复创建 |
| 我的求片 | 电影、剧集分栏；状态徽标：待处理、进行中、已处理、已过期 | 按状态筛选；点击展开详情与处理备注 |
| 无媒体账号 | 空状态说明“求片需要媒体账号” | 按钮跳转开通 / 认领 |

## 角色差异

| 角色 | 差异 |
|---|---|
| user | 提交、查看自己的求片 |
| admin / super_admin | 个人功能同用户；处理他人求片见 [求片处理](/modules/admin-ops) |

## 状态与边界

- TMDB 解析失败：内联错误，可重试或手动检查链接。
- 额度刷新：跨零点自动更新，不依赖前端计时推算。
- 已过期条目：用户可见状态,30 天内不可重复提交(去重窗口不论状态),需等管理员“重新激活”;重新激活后回到待处理,过期时间重新计算,不重复扣积分、已退款的也不会再退。
- 用户侧只显示“管理员已处理”与备注、时间,**不显示处理人**。
- 求片开关关闭时 `/wishes` 返回 404 且菜单不出现;缺少媒体账号时显示空态说明与“去我的媒体”入口,不显示提交卡片。

## 依赖接口

`/wishes/quota`、`/wishes/tmdb/resolve`、`/wishes`（列表与创建）。

## 求片开关

- 管理员可在配置 `wishes.enabled` 中控制成员是否可以提交求片,**默认关闭**。
- 关闭时搜索、搜索结果、发现等页面照常可见;搜索结果上的“求片”按钮置灰,提示“管理员未开放求片”。
- 对应前端特性标志 `wishSubmissionEnabled`;TMDB 未配置自有 Key 时使用内置 Key。
