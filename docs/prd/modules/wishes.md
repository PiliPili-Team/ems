# P7 心愿中心

心愿中心 `/wishes`、心愿管理 `/admin/wishes` 使用独立货币“心愿点数”。状态为数值枚举:待处理、进行中、已处理、已过期;编号为自增整数。

## 目的

用户从影视搜索结果或详情页许愿,按电影或剧集的一季及其集数计价,跟踪处理进度。用户必须拥有有效媒体账号;开关关闭时菜单隐藏且直接访问返回 404。

## 心愿点数与提交

| 子功能 | 展示与交互 |
|---|---|
| 余额 | 今日发放剩余、已购余额、后端返回的 UTC 重置时间与购买入口;每日发放不累积,先扣每日再扣已购 |
| 搜索与详情入口 | 只从搜索结果或详情页发起;没有手动 TMDB 链接或 ID 输入 |
| 电影 | 报价来自后端,默认花费 1 点 |
| 剧集 | 选择一季的单集、多集或整季;仅按未覆盖的集报价,单集默认 1 点、单季默认封顶 60 点;不跨季 |
| 覆盖提示 | 恰好一个库内匹配或他人待处理/进行中的心愿覆盖时,相应集无须点数;全部覆盖不得提交;库查询失败时提示暂不可用并允许提交 |
| 余额不足 | 禁用提交、提示缺口和购买入口;提交时后端重新判定覆盖与计费 |
| 重复心愿 | 同用户、同影视、同季、30 天内所选集有交集时返回已有编号,不扣费 |

## 我的心愿

顶部余额卡;桌面列表与心愿管理同样式但去掉申请人列:影视(海报、标题、年份、类型)、TMDB ID、范围、花费、状态、用户备注与最新处理备注、提交时间各占独立列,简介不在列表展开,影视列限宽约 15rem。点击行或卡片打开详情,显示完整简介、范围、花费拆分、双方备注与提交/处理时间,不显示处理人。支持状态筛选与每页 10 条分页;390px 窄屏变卡片,明暗主题均无横向溢出。无有效媒体账号时显示“心愿需要媒体账号”空态。

提交弹层可选填至多 200 字的用户备注;它与管理员流转时的处理备注分字段保存和返回(`userNote` / `handlingNote`),处理不会覆盖用户备注。

## 策略与退款

每日发放优先级:个人 > 分组(多组取最大) > 等级(normal/VIP/白名单) > 全局默认 5。策略以摘要卡呈现开关、价格、封顶与过期天数,右上角齿轮按钮打开系统/媒体/数据/规则标签的高级设置弹窗;媒体标签有价格试算,数据标签放每日发放,规则标签放带搜索分页的个人/分组规则表;关闭弹窗丢弃未保存修改。配置需 `admin.config.write`,发放规则需 `admin.wish.write`,其他持 `admin.wish.read` 的管理员只读。

待处理心愿过期时,已购部分退回;每日部分仅同一 UTC 日退回,跨日作废。每条心愿至多退款一次,重新激活后再次过期也不重复退款;进行中与已处理不退款。提交与购买都写心愿点数流水。

## 依赖接口

`GET /wishes/balance`、`GET /wishes/quote`、`GET|POST /wishes`、`GET /admin/wishes`、`GET|PUT|DELETE /admin/wishes/allowances`、`GET /admin/wishes/allowances/effective`。
